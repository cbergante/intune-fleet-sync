# Contributing

Open an issue describing the problem before proposing major changes. Keep changes focused, update help and README examples, and use synthetic tenant/device data only.

Run GitHub Actions validation. For behavior changes, add meaningful mocked tests or describe a controlled validation procedure and its results. Never run tests against a production tenant automatically. Do not claim live validation when only static checks were run.

Submit a pull request explaining behavior before/after and validation performed. Keep preview as the default and preserve explicit tenant selection.
